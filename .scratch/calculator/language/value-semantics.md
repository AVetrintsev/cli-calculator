# Значения и вычисление

Материалы спецификации, принятые пользователем в раундах 23–27 [Языка выражений](../issues/04-expression-language.md). Реализация движка этим документом не создаётся.

- Процентный признак сохраняется у напрямую введённых/сохранённых ставок и их сумм/разностей. По поправке раунда 26 умножение/деление с числами или процентами возвращает обычное число без этого признака: 200 * 10% = 20, 10% * 2 = 0,2. Поэтому 200 + 10% * 2 = 200,2, а 200 + (10 * 2)% = 240. Прямое относительное 200 + 10% = 220 неизменно. Результат с этим признаком показывается со знаком %; 10% на экране остаётся 10%, математически это доля 0.1. Обычная 0.1 автоматически процентом не становится.
- Процентный буфер — показанный коэффициент / 100, точно без скрытых рабочих цифр и без повторного округления. 33,3333333333% → 0,333333333333; 30% → 0,3/0.3 по числовой локали. Два дополнительных дробных места получаются сдвигом, не расширением экранного предела. Группирование одинаковых ответов не требует выбирать скрытую трактовку. Правило едино для всех текущих и исторических целей копирования, включая подтверждение; выделенный текст буквальный.
- Момент платежа — отдельное символьное значение start/end и его активный локальный вариант. Доступны константы, локальные переменные, параметры и результаты пользовательских функций, == и != между режимами. Арифметика, упорядочивание и числовое преобразование 0/1 отклоняются. Самостоятельный ответ отображается и копируется локальным символом. Имена защищены как встроенные; обычные правила готовых результатов сохраняются.
- Логические литералы — true/false всегда и да/нет при ru, с той же конфигурацией будущих локалей. Результаты отображаются и копируются уже принятыми Да/Нет или Yes/No; это отдельные выходные тексты, не автоматически новые вводимые псевдонимы. if/and/or/not требуют логические условия, числового угадывания нет; арифметика с логическими значениями отклоняется.
- Один связанный именованный результат сохраняет согласованную трактовку в одном расчёте или пересчёте листа, включая передачу параметром: a=1m; a/a даёт только 1. Отдельные непосредственные вхождения единицы независимы. Сохранение формулы не замораживает навсегда выбранную единицу для будущих независимых расчётов.
- Ошибочные численные трактовки отбрасываются при наличии корректных; если корректных не осталось, нет готового числа и показывается краткая ошибка. Это расширяет фильтр неподдерживаемых итоговых единиц, сохраняет порядок, группирование и полный набор остальных ответов.
- Синтаксис и известность имён проверяются для всего выражения. Только выбранная ветка условия вычисляется численно: if(2>1;4;1/0) = 4, но if(2>1;4;неизвестное_имя) содержит ошибку неизвестного имени. Незавершённый ввод остаётся без готового результата. Эта проверка не требует сама по себе вычислять операции и ограничения единиц неиспользованной ветки.

[Логические обозначения](../localization/values/README.md), [финансовые обозначения](../localization/functions/README.md) и основной каталог переводов содержат соответствующие имена, подписи и описания. Календарный раунд 24 принимает today/yesterday/tomorrow/now и локальные варианты с общим снимком системных часов, динамическими зависимостями и сохранёнными историческими ответами. См. [календарный контракт](calendar.json) и [календарное решение](../issues/19-calendar-and-clock.md). Самостоятельные даты, время и дата-время копируются полностью; раунд 25 уточняет самостоятельные календарные сроки, явные смещения и перенос суток, не выводя их из статических режимов start/end.

Календарный срок хранит число месяцев и фиксированную длительность; год равен двенадцати месяцам. При применении к дате целое суммарное число месяцев сдвигается один раз, затем применяется фиксированная часть. Срок с ненулевой месячной частью копируется с единицами; при нулевой части нормализуется в обычную фиксированную длительность с прежним числовым буфером. Смещения/переносы сохраняются при передаче по имени. Финансовые периоды остаются числовыми параметрами. Раунд 26 принимает равенство сроков по месячной и фиксированной частям; упорядочивание смешанного срока либо календарного с фиксированным требует исходную дату. Чистые месяцы/годы сравниваются по числу месяцев, обычные длительности — по длине.

После частичного сбоя быстрого подтверждения его показанный снимок, включая часы, замораживается до повтора/отказа. Это исключение из динамического обновления, а не изменение семантики сохранённых формул, обычного копирования или листов. Escape оставляет окно открытым и обновляет расчёт; записанная история остаётся.

Рабочее округление дробных результатов — до 30 значащих цифр, точная середина от нуля; следующие операции используют рабочее значение. Десятичные значения в пределах точности сохраняются точно. Отдельный показ до 10 дробных мест не меняет расчёт. Для ненулевого числа, исчезающего при таком показе, допускаются три значащие цифры в пределах 30 дробных мест. Если даже этот предел даёт нуль, показывается ≈ 0, но исходное значение остаётся ненулевым для зависимостей и последующих операций. ≈ 0 принят как готовый ответ: копируется 0, единицы/процент остаются видимыми, история сохраняет настоящее ненулевое значение. Точный и приблизительный нуль не объединяются; одинаковые приблизительные записи группируются по прежнему правилу. Подробности в [численном контракте](numbers.json).

Числовые величины наследуют общие операции над опорным числом с сохранением типа. abs(-1cm) = 1cm, abs(-50%) = 50%: возвращается типизированный результат, а не голая численная доля. Ограничения и переопределения принадлежат типам; процентный обработчик приоритетен перед обработчиком другого сочетающегося типа. Он сохраняет порядок аргументов: 10% + 200 = 200,1 и 10% - 200 = -199,9, тогда как 200 + 10% = 220. Специальное правило раунда 26 для процентного умножения/деления остаётся применимым. См. [модель типов](typed-values.md); остальные частные функции ожидают согласования.
