# Математические модели финансовых расчётов

Дата проверки: 2026-09-11. Исследователь: finance_facts. Основание: [Математические модели финансовых функций](../issues/18-financial-models-research.md); результаты предназначены для [Финансовые расчёты, ставки и периоды](../issues/12-financial-calculations.md).

**Ниже — проверенные математические факты и условные числовые примеры, а не принятые продуктовые решения.** Исследование ограничено постоянным периодическим платежом, накоплением с равными взносами, прибылью/ROI за весь период и простой окупаемостью. Это не расчёт условий конкретного финансового продукта.

## Ставка и период

В PMT/FV `r` — ставка **за один период**, `n` — количество таких периодов; ставка и срок должны использовать одну периодичность. Платежи и ставка постоянны. [Microsoft, PMT](https://support.microsoft.com/en-US/Excel/pmt-function), [LibreOffice, FV](https://help.libreoffice.org/latest/en-US/text/scalc/01/04060118.html).

Если `j` — номинальная годовая ставка с `m` равными начислениями в год, ставка начисления `r = j/m`, эффективная годовая `e = (1+j/m)^m−1`. Если дана именно эффективная годовая `e`, обратное преобразование даёт `r = (1+e)^(1/m)−1`. Последняя формула — алгебраическое следствие годового множителя накопления. Делить любую «годовую ставку» на 12 без определения её смысла нельзя. [Microsoft, EFFECT](https://support.microsoft.com/en-us/excel/functions/effect-function), [OpenStax, Principles of Finance, §8.4](https://openstax.org/books/principles-finance/pages/8-4-stated-versus-effective-rates).

Проверенный пример: `j = 12%`, `m = 12` означает `r = 1%` за месяц и `e = 12.6825030131969720661201%`. Для `e = 12%` эквивалентная месячная ставка составляет приблизительно `0.948879293458297413%`. В этих примерах «месяц» означает один из 12 расчётных периодов; календарные даты и число дней не заданы.

## Общая аннуитетная модель и знаки

`t = 0`: платежи в моменты `1,…,n`; `t = 1`: в моменты `0,…,n−1`, включая первый взнос сразу. Итог оценивается в момент `n`. В соглашении Excel выплаченные деньги отрицательны, полученные положительны: выданный заёмщику кредит `pv > 0`, его платёж `pmt < 0`; вложения вкладчика `pv < 0`, `pmt < 0`, получаемое накопление `fv > 0`. Это соглашение источника, не выбор интерфейса калькулятора. [Microsoft, PV](https://support.microsoft.com/en-us/excel/functions/pv-function), [Microsoft, FV](https://support.microsoft.com/en-us/excel/functions/fv-function).

Обозначим `q = 1+r`, `Sₙ = 1+q+…+q^(n−1)`. Суммирование равных потоков даёт:

```text
pv·qⁿ + pmt·(1+r·t)·Sₙ + fv = 0
Sₙ = (qⁿ−1)/r при r ≠ 0; Sₙ = n при r = 0.
```

Это вывод из модели периодических потоков; уравнение аннуитета также приведено в [документации Apache OpenOffice](https://wiki.openoffice.org/wiki/Documentation/How_Tos/Calc%3A_Derivation_of_Financial_Formulas). При нулевой ставке оно становится `pv+n·pmt+fv=0`, как прямо указано в [Microsoft, PV](https://support.microsoft.com/en-us/excel/functions/pv-function). Поэтому нулевая ставка — определённый случай, а не деление на ноль.

## Платёж по кредиту и накопление

Для полностью погашаемого кредита начальной величины `P ≥ 0`, `n > 0`, итогового долга 0 положительная **величина** платежа:

```text
A = P·qⁿ / ((1+r·t)·Sₙ)
  = P·r·qⁿ / ((qⁿ−1)·(1+r·t))  при r ≠ 0
A = P/n                            при r = 0
Общая сумма платежей = n·A; превышение над телом кредита = n·A−P.
```

Формула получена решением общего уравнения при `pv=P`, `fv=0`, `pmt=−A`. PMT учитывает тело кредита и процент, но не включённые отдельно налоги, комиссии и резервные платежи; Microsoft предлагает умножать PMT на число платежей для общего итога. [Microsoft, PMT](https://support.microsoft.com/en-US/Excel/pmt-function).

Для положительных величин первоначального вложения `P` и каждого взноса `C`:

```text
F = P·qⁿ + C·(1+r·t)·Sₙ
F = P+n·C                         при r = 0
Процентное приращение = F−P−n·C.
```

Это та же модель при `pv=−P`, `pmt=−C`, `fv=F`. При `C=0` остаётся `F=P·qⁿ`; у начала периода каждый регулярный взнос работает на один период дольше, поэтому только взносная часть умножается дополнительно на `q`. [Microsoft, FV](https://support.microsoft.com/en-us/excel/functions/fv-function), [LibreOffice, FV](https://help.libreoffice.org/latest/en-US/text/scalc/01/04060118.html).

Математические границы рассмотренной последовательности: целое `n ≥ 0`, `r > −1`; для единственного определённого кредитного платежа нужно `n > 0`. При `n=0` взносов нет и `F=P`. Отрицательная ставка выше −100% математически допустима; тогда превышение платежей над телом может быть отрицательным. Это следствия формул, не предложение разрешить все такие входы в продукте. Для целого `n` представление `Sₙ` суммой также избегает вычитания близких чисел в `(qⁿ−1)/r` при очень малом `r`.

## Прибыль, ROI и простая окупаемость

Для одной исходной инвестиции `I > 0` и суммарной возвращённой стоимости `R` за весь рассматриваемый период: `прибыль = R−I`, `ROI = (R−I)/I`; процентное представление равно `100·ROI%`. В модели владения активом `R` включает его конечную стоимость и полученные выплаты, например дивиденды; исходное вложение вычитается один раз. OpenStax определяет абсолютную отдачу как доход от выплат плюс изменение стоимости, а относительную — делением на начальную стоимость; годовое приведение рассматривается отдельно. [OpenStax, Principles of Finance, §15.1](https://openstax.org/books/principles-finance/pages/15-1-risk-and-return-to-an-individual-asset).

Следствия: при `R<I` прибыль и ROI отрицательны; при `I=0` данная дробь не определена; срок сам по себе не меняет ROI за весь период. Для дополнительных вложений и затрат необходимы отдельные определения `I` и `R`: формула сама не определяет, какие денежные потоки в них включены. ROI нельзя автоматически считать годовой ставкой или процентом накопления по вкладу с пополнениями.

Простой срок окупаемости при исходной затрате `I > 0` и постоянном положительном **чистом денежном потоке** `K` за период: `T = I/K` периодов. Чистый поток — поступления минус выплаты; бухгалтерская прибыль не тождественна ему. Метод не дисконтирует будущие деньги. [OpenStax, Principles of Accounting, Volume 2, §11.2](https://openstax.org/books/principles-managerial-accounting/pages/11-2-evaluate-the-payback-and-accounting-rate-of-return-in-capital-investment-decisions).

Уточнение модели: дробное `T` предполагает равномерное поступление внутри периода либо интерполяцию. Если вся сумма `K` приходит только в конце периода, первое фактическое покрытие наступает через `ceil(I/K)` полных периодов. При `K≤0` и `I>0` исходная затрата в этой постоянной модели не возвращается; отрицательное частное не является сроком окупаемости. При нерегулярных потоках одного значения `K` недостаточно. Это математические ограничения простой модели; дробную интерполяцию демонстрирует [OpenStax, §11.2](https://openstax.org/books/principles-managerial-accounting/pages/11-2-evaluate-the-payback-and-accounting-rate-of-return-in-capital-investment-decisions).

## Независимо проверенные числовые эталоны

Денежные значения — условные единицы одной валюты. Десятичная точка используется только для однозначной записи эталонов. В первых восьми строках `P=100000`, `n=12`, `j=12%` номинальных годовых, `r=0.01`; для накоплений `C=10000`, кроме явно указанного исключения. Числа с `≈` округлены здесь до 12 дробных знаков.

Метод проверки: Python из существующего окружения, `decimal` с 70 значащими цифрами; PMT независимо найден как `P/Σ(q^(−k))`, `k=1,…,12`, через точные рациональные `Fraction`. FV независимо проверен суммой будущих стоимостей через `Fraction` и последовательным изменением остатка. Кредит проверен рекуррентно `Bₖ=Bₖ₋₁·q−A`; итоговый численный остаток `−7·10⁻⁶⁶`. Для накопления проверены обе рекурсии: `Bₖ=Bₖ₋₁·q+C` и `Bₖ=(Bₖ₋₁+C)·q`. Все проверки прошли; Excel/Calc для этих чисел не запускались.

## Точность и ещё не принятые решения

Внутренняя математическая сумма и расписание платежей, округляемых после каждого начисления, могут различаться. Собственный условный пример: округляем платёж и каждый месячный процент до 0.01 методом half-up. Двенадцать платежей по `8884.88` дают перепогашение `0.03`; после одиннадцати таких платежей закрывающий платёж равен `8884.85`, сумма — `106618.53`. Это проверенная симуляция выбранного для примера округления, **не банковское правило**. Простое округление точного `12·A` до сотых даёт `106618.55`.

Открытые продуктовые решения: смысл годового ввода и преобразование периодов; начало/конец платежа и значение по умолчанию; пользовательские знаки; допустимые границы; входы прибыли/ROI; дробная или дискретная окупаемость; внутренняя точность и режим округления; правила отображения и ошибки. Имена функций, алиасы, формат, валюта и календарная модель остаются пользовательскими решениями. Расчёт по датам, несовпадающие частоты взносов и начислений, комиссии/налоги и договорное округление требуют собственного определённого сценария; настоящий отчёт их не утверждает.
