# Сохранность локальных данных при сбое

Status: open
Type: task
Label: wayfinder:task
Parent: ../map.md
Blocked by: 26, 29

## Question

Проверить ограниченным воспроизводимым экспериментом предложенную схему SQLite-хранения: сохранение целой предметной транзакции, отмену неподтверждённой записи после аварии процесса, согласованный резервный снимок, безопасное восстановление и защищённое изменение версии формата. Для каждого сценария записать фактическое состояние исходной базы, незавершённого действия и резервного файла; отличить подтверждённый успех записи от попытки её выполнить. Подтвердить, какие технические механизмы достаточны для уже принятых правил сохранности данных, и зафиксировать непроверенные границы.

## Context

Техническая AFK-предпосылка [Общее ядро и платформенные оболочки](09-shared-core-and-shells.md). Продуктовые правила и раунд 41 уже приняты; источники — [Локальное хранение, резервирование и перенос](26-durable-local-storage.md), [Шаблоны, сохранение и перенос данных](07-templates-and-data.md) и проект архитектуры. Основной материал эксперимента должен остаться на отдельной ветке.

Использовать только явно обозначенную одноразовую базу с вымышленными документами внутри папки стенда. Нужны реальные SQLite/файловые операции и завершение только собственного вспомогательного процесса; сбой питания и повреждение носителя нельзя объявлять воспроизведёнными одним process kill. Проверка не затрагивает системный буфер, существующие пользовательские базы или их резервные копии. Ошибка записи не считается успехом, повреждённый оригинал сохраняется, восстановление и новая пустая база выполняются только как явно выбранные действия сценария; файлы более нового формата не переписываются старым клиентом.
