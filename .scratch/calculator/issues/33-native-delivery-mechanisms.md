## Question

Какие проверяемые механизмы подходят для уже выбранных Windows C#/WPF и macOS Swift/AppKit: пользовательская установка без обязательных прав администратора, подписанная прямая поставка, тихая проверка обновлений с явной командой установки, сохранение данных и рабочего состояния, отказ при сбое обновления? Сопоставить ограниченный набор готовых средств, проверить границы Windows x64 и macOS 14+ Intel/Apple silicon, требования подписи и совместимость отката приложения с миграцией данных. Не менять принятую политику продукта и не создавать установщики, аккаунты или службы.

## Context

Исследование снимает техническую предпосылку вопроса [Установка, обновления и критерии готовности](10-delivery-and-acceptance.md). Аудитория, платформы, прямая загрузка, подпись, ручная команда установки и сохранение данных уже приняты; окончательные технологии оболочек закреплены в архитектуре. Нужны первичные источники и границы проверок, а не повторный выбор продуктовых правил. Отчёт сохраняется в отдельной исследовательской ветке; основной проект получает проверенный вывод и указатель.
