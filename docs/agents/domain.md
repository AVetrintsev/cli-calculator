# Документация предметной области

## Перед исследованием кода

- Прочитай `CONTEXT.md` в корне репозитория.
- Прочитай решения в `docs/adr/`, относящиеся к исследуемой области.
- Если этих файлов ещё нет, продолжай работу без предупреждений и предложений создать их заранее. Навык `domain-modeling` создаёт их по мере согласования терминов и решений.

## Структура

В проекте используется единый контекст (single-context): общий `CONTEXT.md` в корне и архитектурные решения в `docs/adr/` с именами вида `0001-<decision-slug>.md`.

## Терминология и решения

В названиях задач, гипотезах, предложениях изменений и тестах используй термины из `CONTEXT.md`. Не заменяй их синонимами, которые глоссарий исключает.

Если нужного понятия нет в глоссарии, проверь, действительно ли оно нужно проекту; выявленный пробел отметь для `domain-modeling`.

Если предложение противоречит существующему ADR, явно укажи документ и причину пересмотра решения.
