# Правила работы с ветками

- `main` — основная ветка проекта.
- Для разработки новой функциональности создавай отдельную ветку `feat-<краткое-описание>` от актуальной `main`.
- Для исправления дефекта или некорректного поведения создавай отдельную ветку `fix-<краткое-описание>` от актуальной `main`.
- Перед изменениями проверяй текущую ветку. Если открыта `main`, сначала создай подходящую рабочую ветку.
- Прямые коммиты и прямой push в `main` запрещены. Делай коммиты в рабочей ветке и вноси изменения в `main` только через Pull Request / Merge Request.

## Agent skills

### Issue tracker

Задачи и спецификации хранятся в Markdown в `.scratch/` и версионируются в Git. Перед созданием, чтением или обновлением задач прочитай `docs/agents/issue-tracker.md`.

### Triage labels

Используются пять стандартных меток triage. Перед классификацией задач прочитай `docs/agents/triage-labels.md`.

### Domain docs

Единый контекст: `CONTEXT.md` в корне и решения в `docs/adr/`. Перед исследованием кода прочитай `docs/agents/domain.md`.
